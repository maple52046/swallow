# Server

- Bounded context: Platform-wide. `api-server` and `dashboard` use this term with the same meaning. (`agent` was removed; see [decision 001](../../../decisions/001-system-ownership-boundaries.md).)
- Definition: A physical or virtual compute unit swallow manages, **projected from a provisioner's inventory** rather than created by an operator. It comes into being when the reconciler sees a machine in a provisioner (MAAS, one per site) that has no server yet.
- Allowed meaning: A managed compute unit with a three-layer identity — a swallow-issued opaque `serverId` that is the only thing swallow references it by; a `source` external key of `(siteId, integrationId, providerMachineId)` that is unique and is how the reconciler finds the record; and `hardware` identifiers (system UUID, serial, MACs) used to recognise the same physical machine after re-enrollment. `hostname` and IP address are **observed attributes: nullable, mutable, and not unique** — two sites may both hold `gpu-node-01`, and a machine mid-reinstall has no address. A server's condition is **three independent status axes** (provisioning, membership, health), each owned by a different system and each absent until observed, never a single combined status. Hardware facts the fleet is queried by — GPU inventory, vendor, CPU model, tags — are mirrored with their own freshness; fuller per-machine detail is read live on demand. Ordinary inventory absence retains the projection because it may be transient. An explicit operator deletion is different: it must delete the provisioner's backing Machine first and then remove the Server projection, so reconciliation cannot recreate it.
- Disallowed meaning: A Kubernetes node object, a container, a workload, a management plane cluster, a rack unit, or a monitoring target swallow does not manage. Not a synonym for the OS installation or a provisioning job. Identity is **not** hostname or IP: an earlier definition made both required and unique, which cannot hold across sites and breaks during a reinstall.
- Synonyms: None.
- Deprecated terms: `Host` — a deprecated alias still in parts of the dashboard. `Node` and `Machine` must not be used for a platform Server outside an explicit Kubernetes or provisioner-inventory context. A provisioner's `Machine` is the thing a Server is projected from, not the Server itself.
- Examples: "A server keeps its `serverId` when its MAAS is rebuilt and its `providerMachineId` changes." / "Two sites both have a `gpu-node-01`; they are different servers because their source keys differ." / "Deleting a Server removes its backing MAAS Machine before removing the Swallow projection."
- Related terms: Server Status（the three status axes）, Site, Integration, Provisioning, Cluster, Operation.
- Change note: Reconciled to the platform refoundation ([decisions 001](../../../decisions/001-system-ownership-boundaries.md) and [002](../../../decisions/002-server-identity.md)). The previous definition — hostname/IP as required unique identity, a single operational status, and a team/user owner — described the pre-refoundation model and has been superseded. Explicit deletion was clarified as a provider-first destructive operation; this does not change the retention rule for ordinary inventory absence. The fuller narrative form of this term lives at [`docs/glossaries/server.md`](../../../glossaries/server.md); the two glossary trees are not yet merged, which is tracked separately.
