# Server

- Bounded context: Platform-wide. `api-server`, `agent`, and `dashboard` all use this term with the same meaning.
- Definition: A physical or virtual compute unit managed by the platform. Server is the platform's primary resource entity: it has an identity, an operational status, an optional owner, and an optional physical location.
- Allowed meaning: A managed compute unit that may carry hardware attributes (CPU, memory, GPU), may be placed in the physical topology, may have remote access configured (BMC and SSH), and may run zero or more workloads. Identity is domain-level: hostname and primary IP address are both required at registration and must each be unique across all servers; uniqueness is enforced by the platform, not by the caller. A Server belongs to at most one owner at a time — a team or a user, never both simultaneously. In the current backend a Server record is a minimal **registry record** rather than a complete machine profile: only hostname and IP are required at creation, every other attribute group is optional and unenforced, and a newly registered Server has status `unknown` until monitoring data arrives.
- Disallowed meaning: A Kubernetes node object, a container, a workload, a management plane cluster, a rack unit, or a monitoring target that the platform does not manage as a resource. Server is also not a synonym for the machine's operating system installation or for a provisioning job that targets it.
- Synonyms: None.
- Deprecated terms: `Host` — a deprecated alias for Server that still appears in the dashboard asset domain types and parts of the observability layer. New code and new documents must use Server. `Machine` and `Node` must not be used for a platform Server outside an explicit Kubernetes context.
- Examples: "A newly registered Server has status `unknown` because no monitoring data has been received yet." / "Assigning a Server to a team makes its allocation state team-owned; a Server cannot be owned by a team and a user at the same time."
- Related terms: Server Status（Server 的營運狀態值集）, Owner（由 team 或 user 擁有關係推導）, Allocation State（由 owner 關係推導）, Team, User, Datacenter, Room, Rack, Container, Workload, BMC, SSH Connection.
- Change note: Migrated from the previous single-file `docs/glossaries/server.md` into the per-term glossary format. Attribute-level field lists and response shapes were intentionally left to the `api-server` API contract; this term now records only domain meaning, identity rules, and ownership constraints.
