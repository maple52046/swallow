# Pool

- Bounded context: swallow-wide. `api-server`, `dashboard`, and `cli` use this term with the same meaning.
- Definition: A swallow-owned, installation-wide grouping of Servers used to partition resources for allocation and access — a *resource pool* — that swallow defines and manages as desired state. A Pool exists only in swallow: no provisioner holds it, and a provisioner's own resource pools (MAAS *resource pools*) are only observed on each Server.
- Allowed meaning: A managed resource identified by an opaque, stable swallow-issued `poolId`, with a `name` unique within the installation and an optional `description`. It belongs to no Site, so one Pool may hold Servers of several Sites. A Server is placed in at most one Pool through its own spec (`spec.poolId`, null for no Pool); the placement needs no realization and takes effect when it is written. Deleting a Pool is refused while a Server is placed in it. A Pool is also the unit of access: Users belong to it through Pool Memberships (Pool Role `owner` or `member`), it carries its Sudo Policy defaults, and its Servers' Host Access follows from both; a Platform belongs to the Pool that holds every one of its nodes. "Pool" always means this swallow-owned concept; the phrase "available pool" in Release refers to the provider returning a Machine to its ready state and is not this term.
- Disallowed meaning: Not a Zone (a Zone groups for availability/fault/organization inside one Site; a Pool partitions resources for allocation and access across the installation), not a Site, not a Kubernetes/Slurm Platform, not a provider's "available pool" of ready Machines used when releasing, and not the provisioner's resource pool: a MAAS resource pool a Server is in is an observed fact of that Server (its provider resource pool), never a Pool and never written by swallow.
- Synonyms: Resource Pool.
- Deprecated terms: None.
- Examples: "Create a Pool `research`; nothing changes in MAAS." / "Place `gpu-node-01` (Site A) and `gpu-node-07` (Site B) in Pool `research`; the owners of `research` operate both." / "'Release returns a Machine to the provider's available pool' does not refer to a Pool."
- Related terms: Zone, Site, Server, Pool Membership, Pool Role, Sudo Policy, Host Access, Platform, Release.
- Change note: Added 2026-09-14 to make Pool (resource pool) a swallow-owned, Site-scoped managed concept surfaced under the dashboard *Infrastructure* area, with optional provider realization. Disambiguated from the pre-existing informal use of "available pool" in the Release term. See [decision 071](../../../decisions/071-provisioner-realized-desired-state.md) (provisioner realized desired state). On 2026-10-31 (decision 071) the Pool catalog and Server placement became desired state realized by controllers. On 2026-11-13 ([decision 082](../../../decisions/082-accounts-pool-access-and-directory.md) (accounts, pool access, and directory)) the Pool became the unit of access through Pool Memberships, and the same day it became installation-wide and swallow-only: it no longer belongs to a Site, is no longer realized as a provisioner resource pool, and a placement no longer moves the machine (decision 082).
