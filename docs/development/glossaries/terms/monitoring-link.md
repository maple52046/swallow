# Monitoring Link

- Bounded context: Observability, owned by `api-server` as Platform data; surfaced by `dashboard` and `cli`.
- Definition: A named link from a Platform to a monitoring user interface that belongs to that Platform — for example the Platform's own Grafana that swallow installs on a Slurm Platform's controller or in a Kubernetes Platform's cluster. swallow stores the name and URL as owned display data and shows them where the Platform is managed. Users register links; swallow also registers `Platform Grafana` itself when it installs the Platform's Grafana.
- Allowed meaning: A `name` and an absolute `http`/`https` `url` attached to one Platform, at most ten per Platform with names unique within it, replaced as a whole list when edited. It answers "where is this runtime's own monitoring?" so a user can move from swallow to it in one click. A successful install of the Platform's Grafana replaces (or adds) only the link named `Platform Grafana`, removing the `Omnistat Grafana` or `Device Metrics Exporter Grafana` link swallow wrote for the same Grafana before; uninstalling the Platform removes only those swallow-written links; other links stay user-owned. A link may open a page inside the UI rather than its root: the `Platform Grafana` link swallow writes opens the landing dashboard of the Platform's own Grafana.
- Disallowed meaning: Not a metrics Integration — swallow never connects to, authenticates against, health-checks, or queries a Monitoring Link, and its usage charts keep reading the Site Prometheus, which is also where the linked Grafana reads its data. Not a credential holder (a link carries no secret). Not the metrics Integration's optional Grafana URL, the base address swallow's own charts build Grafana links from: a Monitoring Link is a whole URL swallow stores and displays, even when the one swallow writes opens a dashboard of the Platform's Grafana. Not a way to make swallow scrape the runtime's collectors.
- Synonyms: Platform monitoring link.
- Deprecated terms: None.
- Examples: "Add the Monitoring Link `Runbook` to `research-slurm` so users reach the team's notes from the Platform page." / "Clearing a Platform's Monitoring Links does not stop its Grafana; it only removes the shortcut from swallow." / "Server detail still shows CPU charts from the Site Prometheus while the Slurm Platform links to its own Grafana." / "The Slurm deployment installed the Platform's Grafana, so the Platform page already shows `Platform Grafana`, which opens the Omnistat overview in the primary controller's Grafana." / "A CPU-only Kubernetes Platform's `Platform Grafana` link opens the Servers dashboard of the Grafana in its cluster."
- Related terms: Platform, Integration, Server, Omnistat.
- Change note: 2026-11-03 ([decision 003](../../../decisions/003-metrics-label-contract.md)): the linked Grafana is the Platform's own, installed by swallow and reading the Site Prometheus; no runtime brings a second metrics backend. Added 2026-10-12 with the monitoring integration work so a runtime with its own complete monitoring stack (Omnistat on Slurm) is reachable from swallow without becoming a second metrics backend; see the 2026-10-12 amendment of [decision 003](../../../decisions/003-metrics-label-contract.md) (metrics label contract). 2026-10-21 ([decision 063](../../../decisions/063-omnistat-slurm-observability.md) (omnistat slurm observability)): swallow registers and removes the `Omnistat Grafana` link when it installs and uninstalls Omnistat. 2026-11-03: every Slurm Platform may have its own Grafana, with or without a monitoring feature, so swallow's link is named `Platform Grafana` and replaces the earlier names on the next deploy. 2026-11-03: a Kubernetes Platform's Grafana runs in its cluster, and its `Platform Grafana` link names a workload node's node port. 2026-11-04: the `Platform Grafana` link opens the Grafana's landing dashboard, chosen from the dashboards it provisions, instead of its root; the disallowed meaning that excluded every Grafana deep link swallow generates was meant to keep Monitoring Links apart from the metrics Integration's Grafana URL, so it now names that setting and allows a swallow-written link into the Platform's own Grafana. Platforms deployed earlier get the new link on their next deploy.
