# Subnet DNS

- Bounded context: OS Provisioning. `api-server` and `dashboard` use this term with the same meaning.
- Definition: The DNS servers a provisioner subnet hands to the machines it deploys with a provisioner-assigned or static address on that subnet. For MAAS it is the subnet's `dns_servers`.
- Allowed meaning: An ordered list of up to eight distinct IP addresses per provisioner subnet that swallow owns as desired state (decision 071): a write stores it as the subnet's spec, the Subnet DNS Controller writes it to the provisioner and reads it back, and a change made in the provisioner is Drift, put back at the periodic resync. A subnet seen for the first time is adopted with its current list, and the setting of a subnet the provisioner no longer has is removed; the subnets themselves stay the provisioner's. An empty list means the subnet has none, and such machines fall back to the provisioner's own DNS. It reaches `automatic` and `static` deployments started afterwards; a `dhcp` deployment takes DNS from the network's DHCP server instead. A subnet is identified by the provisioner's own subnet id. A subnet is *attached* — a real network — when a provisioner controller interface is on it, the provisioner serves its DHCP, a machine's boot interface is on it, or a machine NIC with hardware identity (or a bond, VLAN, or bridge built on one) is on it. The provisioner also records host-internal networks (container, Kubernetes, or VM bridges reported by an enrolled host), which are not attached and which deployments never use.
- Disallowed meaning: Not a DNS zone, record, or resolver that swallow models or serves. Not the provisioner's upstream forwarders (MAAS `upstream_dns`), which its own DNS uses. Not a per-deployment or per-Server setting, and not an Integration setting. Not a change to already deployed hosts.
- Synonyms: Subnet DNS servers; MAAS subnet "DNS servers".
- Deprecated terms: None.
- Examples: "Set Subnet DNS on `10.170.168.0/23` to `165.204.124.158` and `165.204.219.249`, then deploy with `automatic`: the deployed netplan lists those two nameservers." / "A Server deployed with `dhcp` on the same subnet uses the DNS servers its site DHCP lease offers."
- Related terms: Network Configuration, OS Deployment, Integration, Provisioner HTTP Proxy, Controller, Drift.
- Change note: Added 2026-10-13 ([decision 058](../../../decisions/058-deployment-dhcp-and-subnet-dns.md)). Servers on site-DHCP networks deployed with a provisioner-assigned address received the provisioner's DNS, and changing it meant leaving swallow for the MAAS UI or CLI. Same day: *attached* added, because hosts enrolled with their OS kept report their Docker and Kubernetes bridges and MAAS records each new CIDR as a subnet. On 2026-10-31 ([decision 071](../../../decisions/071-provisioner-realized-desired-state.md)) swallow began storing each subnet's list as desired state and correcting changes made in the provisioner.
