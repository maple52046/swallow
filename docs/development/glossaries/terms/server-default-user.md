# Server Default User

- Bounded context: swallow-wide (Server). `api-server`, `dashboard`, and `cli` use this term with the same meaning.
- Definition: The account on a deployed Server's operating system that swallow automation logs in as with the Deployment Key, and that host software meant for interactive use is granted to (Docker CE adds it to the `docker` group).
- Allowed meaning: One effective value per Server, resolved in a single place: the value an operator set on that Server when present (source `server`), otherwise the default user of the OS Image the Server was deployed with (source `os_image`), otherwise unknown — automation then keeps its fallback probe over the Site SSH user and built-in candidates. Any deployed Server may have one set; it is how a Server whose OS swallow did not deploy (an existing Server) becomes reachable for automation. Setting it proves a Deployment Key login as that account before it is saved; the operator may give the account's password once so swallow first adds the Deployment Key to that account's `authorized_keys`, and the password is never stored. The result also reports whether the account can use sudo without a password. A value set on the Server belongs to one OS installation: it is cleared when swallow starts a new OS deployment on the Server and when the Server is observed with no OS (`ready` or `allocated`).
- Disallowed meaning: Not a swallow User and not an operator's personal login (operators connect with their own Access Keys). Not the OS Image default user itself — that is the image's property, and only the fallback for a Server without its own value. Not a stored host credential: no password is kept. Not a Site setting: the Site SSH user remains only a probe candidate.
- Synonyms: Login user (UI wording on the Server Connection card).
- Deprecated terms: None.
- Examples: "`lab-compute-2` was deployed from `ubuntu/noble`, so its Server Default User is `ubuntu` from the OS image." / "`tainan-ci` was installed outside swallow; an operator sets its Server Default User to `amd` with the account's password once, swallow installs the Deployment Key, and Docker CE then adds `amd` to the `docker` group." / "Redeploying the Server through swallow clears the value set on it, so the new OS uses its image's default user."
- Related terms: Server, OS Image, Deployment Key, SSH Key, Automation Configuration, Managed Software, Server Lock.
- Change note: Added 2026-10-02 ([decision 045](../../../decisions/045-server-default-user.md)) so existing Servers can be automated and Docker CE can grant its group to the right account; before this the default user was only an OS Image property mirrored onto Servers swallow deployed.
