# Platform Claim

- Bounded context: Platform Management (written by the Platform context on the swallow-owned Server projection; read by Provisioning).
- Definition: The swallow-owned record on a Server that a Platform deployment swallow accepted targets it: the claiming Platform's id and when the deployment was accepted.
- Allowed meaning: Written for every member of a Platform spec when the spec is written (creating a Platform, adding a member) and for every target when a Platform deployment is accepted, with a conditional write per Server so only one Platform can claim a Server. Kept while the Platform is `deploying`, `deploy_failed`, `active`, `uninstalling`, or `uninstall_failed`, because the hosts may still carry platform state. Released when that Platform's uninstall succeeds (with or without deleting the record), when its record is deleted, or when the deployment request is refused. A claimed Server cannot be released directly, nor recovered while it is deployed, nor deleted, and cannot be a target of another Platform's deployment; its Servers are released through the Platform's uninstall with release servers, and can be deleted once that uninstall succeeds or the Platform's record is deleted. The platform controller keeps the members of a present Platform spec claimed (a Platform deployed before specs existed gets its claims when the controller adopts it from its latest deployment) and releases a claim whose Platform no longer exists; a member a spec drops keeps its claim until the change removing it is carried out.
- Disallowed meaning: Not Membership, which is the Platform runtime's own observed answer and can be absent exactly when the claim matters (a deployment that never joined, a failing sync). Not a Node Role or a tenancy allocation (Allocation State). It does not store the Platform's name, which can change, and it never restricts the Workflows that act for the Platform itself (its deployment, repair, or uninstall with release servers).
- Synonyms: None.
- Deprecated terms: None.
- Examples: "gpu-node-04 is claimed by edge-staging while its deployment is `deploy_failed`, so Release and Delete are refused; uninstalling edge-staging releases the claim." / "Two deployments accepted at the same moment for the same Server: the second is refused as already claimed."
- Related terms: Platform, Server, Membership, Platform Lifecycle State, Provider Recovery.
- Change note: Added 2026-10-29 ([decision 067](../../../decisions/067-platform-claim-on-server.md)) so release of a Platform's Servers could be refused without recomputing claims from durable lifecycle history on every request; the deployment-time claim that used to be derived from that history now reads this record. Updated 2026-10-30: deleting a claimed Server is refused too, because Delete removes the node from under the Platform just as a release does. Updated 2026-11-01: claims follow the Platform spec's members and the platform controller keeps them, replacing the backfill at API start.
