# Platform

- Bounded context: Platform Management.
- Definition: A Kubernetes or Slurm runtime environment that Swallow deployed, including a single-node Kubernetes installation. Swallow owns its policy and lifecycle intent, deploys it, observes membership from the runtime's own API, and — for a deployed Kubernetes Platform — manages its in-cluster resources live through the same API.
- Allowed meaning: A Platform is created only by a Swallow deployment, which also produces a durable Operation and a Swallow-owned credential. Uninstall removes the Swallow-deployed runtime from its original targets while retaining the Platform record. Delete removes only the record and Swallow-owned projections. A deployed Kubernetes Platform additionally exposes a live cluster explorer (namespaces, applications, pods, apply, node cordon) that reads and writes the runtime's own API on demand and stores nothing.
- Disallowed meaning: Platform must not mean swallow itself (the system is named `swallow`), a Site, a provisioner Integration, an arbitrary Server group, a Kubernetes workload, a durable copy of the runtime internal state, or a single-software installation (a Docker CE, Podman, or NFS install is Managed Software, whose deploy target is one software rather than a multi-component runtime). Delete must not imply host-side uninstall. A Platform is not a registration of a runtime Swallow did not deploy: Swallow manages only self-deployed Platforms, and the public API no longer registers an existing one (the OS-provisioning import of an existing Server is unrelated and not a Platform).
- Synonyms: None.
- Deprecated terms: Cluster, when naming the Swallow aggregate or public resource; Forget, when deleting a Platform record; register/registered, when naming a public way to attach a runtime Swallow did not deploy (kept only as a one-release compatibility state for pre-existing records).
- Examples: A standalone k0s installation Swallow deployed is one Kubernetes Platform. A pre-existing `registered` record can still be deleted but never uninstalled and offers no cluster explorer. A failed uninstall retains the Platform for diagnosis and retry.
- Related terms: swallow, Server, Node Role, Kubernetes Topology, Kubernetes Application, Operation, Platform Lifecycle State, Integration, Exporter Ownership, Managed Software.
- Change note: Renamed from Cluster on 2026-09-03 so the aggregate covers single-node and multi-node runtimes without implying a particular topology ([decision 014](../../../decisions/014-platform-resource-language.md)). Kubernetes cluster remains valid only when referring to the external technology itself. On 2026-09-05, `swallow` was added to Disallowed meaning so `Platform` never denotes the system itself ([decision 015](../../../decisions/015-platform-term-disambiguation.md)). On 2026-09-19, narrowed to self-deployed only and given a live Kubernetes cluster explorer; the public register-existing path was removed, leaving `registered` a one-release compatibility state ([decision 032](../../../decisions/032-self-deployed-platform-management.md)).
