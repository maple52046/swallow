# Integration

- Bounded context: swallow-wide.
- Definition: A registered external system that swallow talks to, scoped to exactly one Site. swallow owns the registry of Integrations; no external system knows which systems swallow should talk to.
- Allowed meaning: A swallow-owned record identified by an opaque, stable `integrationId` — persisted in every Server source, so it must never be reissued for a different system — carrying `siteId`, a `kind`, an `endpoint`, a write-only `credentialRef`, and an `enabled` flag. Kinds are `provisioner` (MAAS — read inventory, deploy and release operating systems), `metrics` (central TSDB — query with PromQL), `platform` (Kubernetes API or Slurm — read live membership and, for Kubernetes, manage in-cluster resources), and `repository` (the Site's Local Repository — Pulp — at most one per Site; its `contentOrigin` setting is where Servers read content, apart from the endpoint swallow calls). An Integration may be registered but paused. A `platform` Integration is created only by a successful swallow deployment's completion hook; users register `provisioner`, `metrics`, and `repository` Integrations, but not `platform` ones. A Kubernetes `platform` Integration may also carry a second, write-only operator credential, used only for an admin's in-cluster writes, while its `credentialRef` stays read-only ([decision 032](../../../decisions/032-self-deployed-platform-management.md)).
- Disallowed meaning: Not a Site, a Server, a Platform, or the external system itself; the Integration is swallow's registration of it. A credential is never returned by any API in any form, including redacted — it is write-only. The `platform` kind names the external Kubernetes/Slurm technology, not the `Platform` aggregate. A `platform` Integration is not a user-facing way to attach a runtime swallow did not deploy: the public create API rejects `kind=platform` ([decision 032](../../../decisions/032-self-deployed-platform-management.md) (self deployed platform management)).
- Synonyms: None.
- Deprecated terms: None.
- Examples: "A `provisioner` Integration reconciles machines into Server projections." / "A MAAS spanning two Sites is two Integrations, because an Integration serves exactly one Site."
- Related terms: Site, Server, OS Provisioning Provider, Staleness, Machine, Provider Adapter, Provider Interface, Local Repository.

The kind names the external technology, kept per [decision 015](../../../decisions/015-platform-term-disambiguation.md) (platform term disambiguation) / decision 015; the canonical kind is `platform` (its one-release `cluster` alias was removed on 2026-10-31, [decision 074](../../../decisions/074-retire-schema-v2-and-deprecated-aliases.md) (retire schema v2 and deprecated aliases)). On 2026-09-19, a `platform` Integration became deployment-created only — the public create API rejects `kind=platform` — because swallow manages only self-deployed Platforms ([decision 032](../../../decisions/032-self-deployed-platform-management.md)). 2026-10-30 ([decision 070](../../../decisions/070-core-providers-and-extensions.md) (core providers and extensions)): an Integration is the registration of one Provider Adapter at one Site — `provisioner` and `metrics` register adapters of the OS provisioning and metrics Provider Interfaces, and `platform` registers a Platform Module's live connection. The store and the Workflow executor are installation-wide adapters and are not Integrations. On 2026-11-05 a Kubernetes `platform` Integration gained its second, operator credential ([decision 032](../../../decisions/032-self-deployed-platform-management.md)). On 2026-11-06 the `repository` kind was added: it registers the Site's Local Repository, an adapter of the Local Repository Provider Interface ([decision 078](../../../decisions/078-local-repository.md) (local repository)).
