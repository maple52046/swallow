# Boot ISO

- Bounded context: OS Provisioning. `api-server`, `dashboard`, and `cli` use this term with the same meaning.
- Definition: A swallow-built boot ISO for one provisioner Integration: when a machine boots it, it takes an address from the site's own DHCP and then boots through that provisioner's MAAS rack — on BIOS firmware with iPXE, which chains the rack's pre-loader (`http://<rack>:5248/ipxe.cfg`); on UEFI firmware with the ISO's own GRUB, which loads the rack's per-MAC GRUB configuration (`http://<rack>:5248/grub/grub.cfg-<mac>`).
- Allowed meaning: Built on demand by an operator, who chooses the provisioner Integration and gives the rack address; swallow renders the iPXE script and the GRUB configuration from its fixed templates (no free-form script) and packages them with pinned iPXE binaries and a GRUB built for the ISO into one ISO that boots on both BIOS and UEFI. The UEFI path goes through MAAS's own UEFI boot because only then does MAAS record a UEFI boot and give the Machine the EFI system partition a UEFI deployment needs. swallow stores the file and serves it, unauthenticated and with HTTP Range, at a URL derived from the installation's Boot Media base URL and the Boot ISO's id; the BMC or hypervisor reads it at every boot. A **rebuild** re-renders both boot paths from the current templates for the same rack and replaces the file at the same URL, so a template change reaches every Server using the ISO without touching its Boot Media. A Boot ISO is selected by a Server's Boot Media, and only a Server of the same Integration may select it. It cannot be deleted while a Server's enabled Boot Media uses it.
- Disallowed meaning: Not an OS Image and not what is installed on a Server. Not the provisioner's own boot resources, which the ISO only chains to. Not signed for Secure Boot (neither its iPXE nor its GRUB): a Server booting it must have Secure Boot off. Not an installation file supplied outside swallow (that model is retired). Not a way to choose a Server's firmware mode: the firmware decides which hand-off runs.
- Synonyms: iPXE boot ISO; boot loader ISO (operator wording).
- Deprecated terms: The installation's Boot Media ISO (`SWALLOW_API_BOOT_MEDIA_ISO_PATH`), replaced by Boot ISOs built in swallow.
- Examples: "An operator builds a Boot ISO named `tainan-rack` for the Tainan MAAS integration with rack address `10.170.168.20`; BIOS machines chain to `http://10.170.168.20:5248/ipxe.cfg`, while UEFI machines boot its GRUB, take a lease, and load `http://10.170.168.20:5248/grub/grub.cfg-52:54:00:af:de:01`." / "`tainan-ci` enables Boot Media with the `tainan-rack` Boot ISO; a Boot ISO of another Site's provisioner is not offered." / "`tainan-rack` was built before the UEFI hand-off, so a UEFI Server booting it got no EFI partition and failed installing GRUB; rebuilding it fixed every Server using it."
- Related terms: Boot Media, BMC, Hypervisor, OS Provisioning Provider, Integration, Site, Server.
- Change note: Added 2026-10-05 ([decision 049](../../../decisions/049-boot-iso-builder.md)) when swallow began building per-provisioner iPXE ISOs instead of serving one installation-supplied file. Updated 2026-10-13 ([decision 057](../../../decisions/057-uefi-boot-iso-hand-off.md)): UEFI firmware boots a GRUB built into the ISO that loads MAAS's per-MAC GRUB configuration instead of running iPXE, because MAAS recorded iPXE boots as BIOS and gave UEFI Machines no EFI system partition (a GRUB chained from iPXE gets no network state); a Boot ISO can be rebuilt in place.
