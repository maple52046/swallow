# Platform Lifecycle State

- Bounded context: Platform Management.
- Definition: The current lifecycle of a Platform, derived by the backend from its deployment and uninstall Workflows rather than inferred from membership or connectivity.
- Allowed meaning: The value set is `registered`, `planned`, `deploying`, `deploy_failed`, `active`, `uninstalling`, `uninstall_failed`, or `uninstalled`. `registered` means there is no swallow deployment provenance; it is a one-release compatibility state for pre-existing records only — the public API no longer produces a new `registered` Platform ([decision 032](../../../decisions/032-self-deployed-platform-management.md) (self deployed platform management)). `planned` means the Platform was created from its spec and its install waits on its Change Plan, so no deployment exists yet. `active` means the latest deployment succeeded and no newer uninstall determines the state. `uninstalled` means the latest uninstall succeeded while the Platform record remains.
- Disallowed meaning: Lifecycle State must not be derived from a nullable Integration, membership count, sync freshness, or host reachability. It must not describe the execution status of one Workflow.
- Synonyms: None.
- Deprecated terms: Waiting for deployment, when used for every Platform without an Integration.
- Examples: A failed initial deployment is `deploy_failed` even if some hosts contain k0s state. A retrying uninstall is `uninstalling`. An uninstall that succeeds removes the Platform record, so a removed Platform has no lifecycle state left; only records uninstalled before every successful uninstall removed the record still show `uninstalled`, until a record-only delete.
- Related terms: Platform, Workflow, Membership, Integration.
- Change note: Added on 2026-08-29 to make Platform lifecycle a provider-owned aggregate read model. On 2026-09-19, `registered` was narrowed to a one-release compatibility state after the public register-existing path was removed ([decision 032](../../../decisions/032-self-deployed-platform-management.md)). On 2026-10-29, an uninstall may also delete the record on success, so `uninstalled` is no longer guaranteed to be observable ([decision 010](../../../decisions/010-cluster-lifecycle-actions.md) (cluster lifecycle actions) amendment). On 2026-11-01 `planned` was added for a Platform created from its spec whose install waits on its Change Plan ([decision 076](../../../decisions/076-change-plans.md) (change plans)). On 2026-11-02 the example was corrected to the platforms contract: deleting a Platform runs its uninstall, and a successful uninstall always removes the record.
