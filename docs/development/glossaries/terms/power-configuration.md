# Power Configuration

- Bounded context: swallow-wide (Server). `api-server`, `dashboard`, and `cli` use this term with the same meaning.
- Definition: The power driver a Server's provisioner uses to switch and read the Server's power, together with that driver's connection parameters — for MAAS, the Machine's `power_type` and `power_parameters`.
- Allowed meaning: The **driver** is the provisioner's own name for how it reaches power (`ipmi`, `redfish`, `virsh`, `manual`, or none). Drivers swallow can write belong to a **family**, which decides the parameters and the functions a Server has beyond switching power: `bmc` (`ipmi`, `redfish`; parameters address, username, password) and `virsh` (a libvirt virtual machine; parameters hypervisor URI `qemu+ssh://[user@]host[:port]/system`, the domain name or UUID as power ID, optional password). **Control** is what the driver lets the provisioner do: `none` (no driver — the provisioner can neither switch nor read power, so it cannot inspect or deploy the Server), `manual` (a person switches power and its state cannot be read), or `automatic` (the provisioner switches and reads power itself). The facts are provisioner-owned: swallow reads them live and writes them through to the provisioner, never stores them, and treats the password as write-only. A virtual machine that belongs to a provisioner VM host takes its power from that VM host, so its Power Configuration is read-only in swallow. In code each family is served by a power adapter; "power adapter" is implementation vocabulary, not operator language.
- Disallowed meaning: Not the BMC — a virtual machine has a Power Configuration but no BMC. Not the Redfish capability: the `redfish` driver only says how the provisioner switches power, and Redfish Boot Media is a probe of the BMC whatever its driver; Redfish is never a family of its own. Not the power state (`on`/`off`), which the Power Configuration lets the provisioner read. Not a swallow-held credential, and not management of a provisioner VM host or of the hypervisor's SSH access, which the provisioner needs before it can use a `virsh` driver.
- Synonyms: Power settings (UI wording); MAAS "Power configuration".
- Deprecated terms: None.
- Examples: "`simple-pig` is a libvirt VM on `tainan-ci`; its Power Configuration is driver `virsh`, address `qemu+ssh://maas@tainan-ci.lab/system`, power ID `simple-pig`, so MAAS can power it off and swallow sees its enlistment end." / "`tainan-node01`'s Power Configuration is driver `ipmi` in the `bmc` family; its BMC still offers Redfish Boot Media." / "A New Machine whose enlistment finished with no driver has control `none`, so its inspection stops with `power_configuration_required`."
- Related terms: Server, BMC, Boot Media, Server Enrollment, OS Provisioning Provider, Machine, Server Lock.
- Change note: Added 2026-10-09 ([decision 054](../../../decisions/054-provisioner-power-configuration.md)). Virtual machines enrolled from a remote libvirt hypervisor had no power driver, so their enrollment power-off could never be observed, and swallow could only read power facts. The term separates power control, which every Server needs, from the BMC, which only physical Servers have, and makes swallow write the provisioner-owned facts through instead of requiring the provisioner's UI.
