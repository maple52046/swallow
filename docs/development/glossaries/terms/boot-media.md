# Boot Media

- Bounded context: swallow-wide (Server, OS Provisioning). `api-server`, `dashboard`, and `cli` use this term with the same meaning.
- Definition: A Server's setting that its BMC mounts a Boot ISO as virtual media and boots it first, so the Server takes an address from the site's own network and then chains to the Site's provisioner — for networks where the provisioner cannot run DHCP.
- Allowed meaning: Swallow-owned intent per Server: whether the Server should boot a Boot ISO first (`enabled` true or false), which Boot ISO (one built for the Server's own provisioner Integration), plus the outcome of the last apply. Enabling it, or choosing another Boot ISO while enabled, is a **preflight**: swallow probes the BMC's Redfish capability, mounts the chosen Boot ISO, sets the boot override, and saves the setting only when all of that succeeded on that Server. Because a BMC may lose the mount or the override later, every OS Deployment on an enabled Server first runs an **ensure** Task that checks the BMC and re-applies what is missing, using the Boot ISO URL frozen when the deployment was accepted. Disabling saves the setting and makes a best-effort attempt to eject the ISO and clear the override. Operators never type an ISO URL; it is derived from the Boot ISO.
- Disallowed meaning: Not an OS Image and not what is installed on the Server; the ISO only gets the machine to the provisioner. Not the provisioner's own PXE or DHCP. Not the BMC's live state: whether the ISO is mounted now is read from the BMC, never assumed from the setting. Not a per-Server ISO URL. Not the Boot ISO itself (the file); Boot Media is the per-Server use of one.
- Synonyms: iPXE boot loader (operator wording).
- Deprecated terms: "The installation's ISO" as the thing Boot Media mounts: replaced by a chosen Boot ISO (decision 049). A setting enabled before that change has no Boot ISO until one is chosen.
- Examples: "`tainan-ci` lives on a network with its own DHCP, so an operator enables Boot Media on it with the `tainan-rack` Boot ISO; the preflight mounts it through Redfish and sets the boot override." / "Before each RAM deploy of `tainan-ci`, the `ensure-boot-media` Task finds the ISO still mounted and the override still set, and re-applies them anyway." / "The BMC lost the override after a firmware update; the next deploy's ensure Task sets it again."
- Related terms: Boot ISO, BMC, Server, OS Deployment, Deploy Target, Task, Server Lock, OS Provisioning Provider.
- Change note: Added 2026-10-03 ([decision 047](../../../decisions/047-redfish-boot-media.md)) so Servers on externally served networks can be deployed without mounting an ISO by hand at every boot. Updated 2026-10-05 ([decision 049](../../../decisions/049-boot-iso-builder.md)): the setting selects a swallow-built Boot ISO of the Server's provisioner instead of the installation's single ISO.
