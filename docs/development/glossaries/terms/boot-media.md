# Boot Media

- Bounded context: swallow-wide (Server, OS Provisioning). `api-server`, `dashboard`, and `cli` use this term with the same meaning.
- Definition: A Server's setting that a Boot ISO is attached to it and booted first, so the Server takes an address from the site's own network and then chains to the Site's provisioner — for networks where the provisioner cannot run DHCP. How the ISO is attached is the Boot Media **method**: `redfish` (a physical Server's BMC mounts it as virtual media) or `libvirt` (swallow puts it on a virtual machine's CD-ROM on its Hypervisor).
- Allowed meaning: Swallow-owned intent per Server: whether the Server should boot a Boot ISO first (`enabled` true or false), which Boot ISO (one built for the Server's own provisioner Integration), plus the outcome of the last apply. The method follows the Server's Power Configuration: a `bmc`-family driver gives `redfish`; a `virsh` driver whose address names a Hypervisor gives `libvirt`; anything else has no method. Enabling it, or choosing another Boot ISO while enabled, is a **preflight**: swallow probes the method (the BMC's Redfish capability, or the Hypervisor's domain and storage pool), attaches the chosen Boot ISO, directs the boot at it, and saves the setting only when all of that succeeded on that Server. Because a BMC may lose the mount or the override later, every hardware inspection and OS Deployment on an enabled Server first runs an **ensure** Task that re-applies it. Disabling saves the setting and makes a best-effort attempt to detach the ISO and clear the boot direction. Operators never type an ISO URL; it is derived from the Boot ISO.
- Disallowed meaning: Not an OS Image and not what is installed on the Server; the ISO only gets the machine to the provisioner. Not the provisioner's own PXE or DHCP. Not the live state: whether the ISO is attached now is read from the BMC or the Hypervisor, never assumed from the setting. Not a per-Server ISO URL. Not the Boot ISO itself (the file); Boot Media is the per-Server use of one. Not the provisioner's power driver: the `redfish` method does not need the provisioner's `redfish` driver, and the `libvirt` method never switches power.
- Synonyms: iPXE boot loader (operator wording).
- Deprecated terms: "The installation's ISO" as the thing Boot Media mounts: replaced by a chosen Boot ISO (decision 049). A setting enabled before that change has no Boot ISO until one is chosen.
- Examples: "`tainan-ci` lives on a network with its own DHCP, so an operator enables Boot Media on it with the `tainan-rack` Boot ISO; the preflight mounts it through Redfish and sets the boot override." / "Before each RAM deploy of `tainan-ci`, the `ensure-boot-media` Task finds the ISO still mounted and the override still set, and re-applies them anyway." / "`lab-afde-mi308-1` is a libvirt VM on `tainan-ci`; its Boot Media uses the `libvirt` method, so the `tainan-rack` Boot ISO is uploaded to `tainan-ci` and put on the VM's CD-ROM, which boots first."
- Related terms: Boot ISO, BMC, Hypervisor, Power Configuration, Server, OS Deployment, Deploy Target, Task, Server Lock, OS Provisioning Provider.
- Change note: Added 2026-10-03 ([decision 047](../../../decisions/047-redfish-boot-media.md)) so Servers on externally served networks can be deployed without mounting an ISO by hand at every boot. Updated 2026-10-05 ([decision 049](../../../decisions/049-boot-iso-builder.md)): the setting selects a swallow-built Boot ISO of the Server's provisioner instead of the installation's single ISO. Updated 2026-10-09 ([decision 055](../../../decisions/055-libvirt-virtual-machine-enrollment.md)): Boot Media has a method, and libvirt virtual machines on a Hypervisor use the `libvirt` method.
