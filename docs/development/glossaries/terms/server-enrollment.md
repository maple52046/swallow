# Server Enrollment

- Bounded context: swallow-wide (OS Provisioning, Server). `api-server`, `dashboard`, and `cli` use this term with the same meaning.
- Definition: The operator action that puts a physical machine into a provisioner's inventory so that reconciliation projects it as a Server. swallow guides two paths: **network boot**, where the machine is power-cycled and boots from the network into the provisioner's enrollment (directly by PXE, or through Boot Media when its network is not served by the provisioner's DHCP), and **existing OS**, where a swallow program run on a host that keeps its operating system registers it with the provisioner without a reboot.
- Allowed meaning: A network-boot enrollment ends with the Server in `new`; swallow then inspects its hardware with an `inspect-hardware` Workflow, automatically when the Integration allows it, which waits until the provider's enrollment has finished (for MAAS, the power-off at the end of enlistment) and brings the Server to `ready`. An existing-OS enrollment ends with the Server in `deployed`, with its hardware recorded from the running OS; it is never inspected automatically because inspection reboots the machine. Either way the Server and its `serverId` come from reconciliation, not from the enrollment.
- Disallowed meaning: Not creating or importing a Server record: swallow has no such operation (decision 002). Not an OS Deployment, and not hardware inspection itself (Inspect re-inventories a machine already in the inventory). Not registering a Platform. Not the provisioner's own UI action.
- Synonyms: Adding Servers (UI wording); enlistment (MAAS wording, network-boot path only).
- Deprecated terms: Server import; manual Server registration.
- Examples: "The operator power-cycles `gpu-07` into PXE; MAAS enlists it, swallow shows it as New, waits for it to power off, and inspects it to Ready." / "`tainan-ci` sits on a network with its own DHCP, so its Boot Media is enabled before the enrollment boot." / "`db-03` already runs Ubuntu; the enrollment command from **Add servers** downloads the swallow CLI from the installation and registers it, and it appears as Deployed."
- Related terms: Server, Machine, OS Provisioning State, OS Provisioning Provider, Boot Media, Workflow, Server Default User.
- Change note: Added 2026-10-06 ([decision 053](../../../decisions/053-server-enrollment-and-automatic-inspection.md)). swallow had no word for how a machine reaches the provisioner's inventory; "import" was retired by decision 002 because it meant creating a record, so the new term names only the provider-side step and keeps reconciliation as the only origin of a Server.
