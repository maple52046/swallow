# Tag

- Bounded context: swallow-wide. `api-server`, `dashboard`, and `cli` use this term with the same meaning.
- Definition: An operator-facing label attached to a Server. swallow owns every manual tag: the Server's spec carries the complete set of its manual tags, and the Server Controller makes the provisioner carry exactly that set (decision 071). An automatic tag — computed by the provisioner, such as a MAAS tag with an XPath `definition` — is provider-owned and only observed. A tag is a flat name and carries real operational meaning: the `amd-gpu` tag derives Server Type and selects the RDC exporter, and tags drive the Prometheus and Ansible discovery filters.
- Allowed meaning: A Server's `spec.tags` (its manual tags, swallow-owned) and its observed `status.tags` (every tag the provisioner reports), of which `status.automaticTags` is the provider-computed subset. Server Type and discovery read the observed tags. A tag edit, for one Server or a batch, writes the spec in one store transaction; the provisioner converges asynchronously and the Server's Conditions report when it has. A manual tag added or removed outside swallow (for example in the MAAS UI) is Drift and is reverted at the Controller's periodic resync. The first observation of a Server is adopted as its spec without changing the provisioner. On a provisioner without tag support the spec is kept and the Server reports `capability_missing`; such tags are not observed, so they do not drive Server Type or discovery.
- Disallowed meaning: Not an OS Image tag (a separate swallow-owned label on images; see decision 025), not a Zone or Pool (those are groupings), not a Server status, and not a hardware probe (a machine that physically has a GPU but is untagged is still `cpu` for targeting). An automatic tag is never part of a spec and cannot be assigned or removed through swallow.
- Synonyms: Label; manual tag (a tag swallow owns), automatic tag (a tag the provisioner computes).
- Deprecated terms: Effective tags (the former union of provider tags and swallow-owned fallback tags).
- Examples: "Adding the `amd-gpu` tag makes a Server an AMD GPU server, so it runs the RDC exporter and appears in that scrape job." / "Someone removes `rack-a` from a machine in the MAAS UI; the Server shows `drifted` until the next resync puts it back."
- Related terms: Server, Server Type, Controller, Condition, Drift, OS Provisioning Provider, Exporter Ownership, OS Image.
- Change note: Added 2026-09-15 for Server tag editing (single and batch), with the capability-first, swallow-owned-fallback ownership of decision 031. On 2026-10-31 ([decision 071](../../../decisions/071-provisioner-realized-desired-state.md)) swallow took ownership of every manual tag through the Server spec, the edit stopped driving the provisioner directly, and the swallow-owned fallback was retired.
