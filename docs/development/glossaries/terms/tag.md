# Tag

- Bounded context: swallow-wide. `api-server`, `dashboard`, and `cli` use this term with the same meaning.
- Definition: A user-facing label attached to a Server. swallow owns every manual tag: the Server's spec carries the complete set of its manual tags, and the Server Controller makes the provisioner carry exactly that set ([decision 071](../../../decisions/071-provisioner-realized-desired-state.md) (provisioner realized desired state)). An automatic tag — one the provisioner computes or maintains itself, such as a MAAS tag with an XPath `definition` or the `virtual` tag MAAS commissioning keeps on machines that are not physical — is provider-owned and only observed. A tag is a flat name and carries real operational meaning: the `amd-gpu` tag derives Server Type and selects the RDC exporter scrape job, and tags drive the Prometheus and Ansible discovery filters.
- Allowed meaning: A Server's `spec.tags` (its manual tags, swallow-owned) and its observed `status.tags` (every tag the provisioner reports), of which `status.automaticTags` is the automatic subset. Server Type and discovery read the observed tags. A tag edit, for one Server or a batch, writes the spec in one store transaction; the provisioner converges asynchronously and the Server's Conditions report when it has. A manual tag can also be deleted or renamed across a Site: every spec that names it changes in one transaction, then the provisioner deletes or renames the tag, and renaming onto an existing manual tag merges the two. A manual tag added or removed outside swallow (for example in the MAAS UI) is Drift and is reverted at the Controller's periodic resync. The first observation of a Server is adopted as its spec without changing the provisioner. On a provisioner without tag support the spec is kept and the Server reports `capability_missing`; such tags are not observed, so they do not drive Server Type or discovery. swallow can remove an automatic tag from Servers (when the provisioner maintains it without a rule) or delete it; that is an action written to the provisioner at once, not desired state, and when the provisioner applies the tag again swallow accepts it.
- Disallowed meaning: Not an OS Image tag (a separate swallow-owned label on images; see decision 071), not a Zone or Pool (those are groupings), not a Server status, and not a hardware probe (a machine that physically has a GPU but is untagged is still `cpu` for targeting). An automatic tag is never part of a spec, is never Drift, and cannot be assigned or renamed through swallow; one the provisioner computes from a rule cannot be removed from a single Server either, only deleted.
- Synonyms: Label; manual tag (a tag swallow owns), automatic tag (a tag the provisioner computes or maintains).
- Deprecated terms: Effective tags (the former union of provider tags and swallow-owned fallback tags).
- Examples: "Adding the `amd-gpu` tag makes a Server an AMD GPU server, so it appears in the RDC exporter's scrape job." / "Someone removes `rack-a` from a machine in the MAAS UI; the Server shows `drifted` until the next resync puts it back." / "An admin removes `virtual` from a VM; MAAS adds it again at the next commissioning, and the Server does not show `drifted`."
- Related terms: Server, Server Type, Controller, Condition, Drift, OS Provisioning Provider, OS Image.
- Change note: Added 2026-09-15 for Server tag editing (single and batch), with the capability-first, swallow-owned-fallback ownership of [decision 069](../../../decisions/069-swallow-owns-desired-state.md) (swallow owns desired state). On 2026-10-31 (decision 071) swallow took ownership of every manual tag through the Server spec, the edit stopped driving the provisioner directly, and the swallow-owned fallback was retired. 2026-11-03: swallow does not install the RDC exporter on hosts, so `amd-gpu` selects only the RDC scrape job. 2026-11-11: an automatic tag became one the provisioner computes or maintains, so MAAS's `virtual` (set by its commissioning, with no definition) is observed only instead of being removed as drift; swallow gained Site-wide deletion and rename of a tag, and removal or deletion of an automatic tag as an action.
