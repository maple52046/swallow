# BMC

- Bounded context: swallow-wide (Server). `api-server`, `dashboard`, and `cli` use this term with the same meaning.
- Definition: A physical Server's baseboard management controller — the out-of-band controller that powers the machine, exposes its console, and (when it offers Redfish virtual media) can present a remote ISO to the host as a boot device.
- Allowed meaning: The controller and its connection facts: address, account, password, and the power driver the provisioner uses (`power_type`, for example `ipmi` or `redfish`). These are the Power Configuration of a Server whose driver belongs to the `bmc` family; only that family has a BMC. Those facts are owned by the provisioner (MAAS enlists and holds them); swallow reads them live for each use, may write them through as the Server's Power Configuration, and never stores the password. The **Redfish capability** of a BMC is swallow's own probe result for one Server: whether the Redfish service answers at the BMC address, which Redfish System is the host, whether that System offers virtual media (CD) and boot override (`Once`, `Continuous`), the BMC's vendor and firmware version, and when it was probed (`probedAt`). It is owned data with a probe time, refreshed by swallow, and never written back to the provisioner. The probe is made against the BMC address whatever the provisioner's power driver is: a BMC that the provisioner drives over IPMI can still offer Redfish.
- Disallowed meaning: Not the provisioner's power driver — `power_type = redfish` only says how the provisioner switches power, not that the BMC can mount virtual media, and `power_type = ipmi` does not rule Redfish out. Not a swallow-held credential. Not the host operating system or its SSH login (that is the Server Default User). A virtual machine has no BMC, even when its Power Configuration (driver `virsh`) has an address. Not a power type of its own for Redfish: Redfish is a function of the BMC.
- Synonyms: Management controller (UI wording on the Server Summary card); out-of-band controller.
- Deprecated terms: None.
- Examples: "`tainan-ci`'s BMC is an AMI MegaRAC; MAAS drives its power over IPMI, and swallow's Redfish probe found virtual media and `Continuous` boot override on System `Self`." / "A BMC whose firmware cannot mount an HTTP ISO has a Redfish capability without virtual media, so Boot Media cannot be enabled on that Server."
- Related terms: Server, Power Configuration, Boot Media, OS Provisioning Provider, Machine, Server Lock.
- Change note: Added 2026-10-03 ([decision 047](../../../decisions/047-redfish-boot-media.md)), promoting the pending term, because Boot Media needs a precise split between the provisioner-owned BMC connection facts and swallow's own Redfish capability probe; MAAS reports only the power driver. 2026-10-09 ([decision 054](../../../decisions/054-provisioner-power-configuration.md)): the connection facts are the Power Configuration of a `bmc`-family driver, which swallow may now write through; a `virsh` driver's address is not a BMC.
