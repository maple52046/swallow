# Kubernetes 管理重構：自部原則 + 叢集 explorer（Consolidated Plan）

- Consolidated: 2026-09-19 09:42
- Scope: `api-server`, `dashboard`, root `docs/`

## 1. Purpose

把 swallow 的 Kubernetes 管理，從「自部 k0s 生命週期 + 成員觀測」擴成一個對**自己佈署出來的**
叢集可讀寫的叢集內管理面（cluster explorer），同時把產品邊界定調清楚：swallow 只管理自己
佈署出來的 runtime，operator 不得再把既有 Kubernetes / Slurm 叢集掛進來管。

## 3. Consolidated Background

swallow 既有的 Kubernetes 能力只到「自部 k0s 生命週期（deploy / uninstall / repair）+ 成員
觀測（membership sync，只讀 nodes）」。API 仍能註冊既有叢集（`origin=registered`），但 dashboard
未暴露該路徑。參考兩個經典 k8s 管理主控台後確立：

- Rancher：自建叢集的「雙平面」——lifecycle（provisioning/CAPR CR）與 cluster explorer（Steve +
  proxy）分離；憑證存成 Secret；day-2 宣告式欄位 + controller。
- Portainer CE：K8s Environment 的「意見化資源樹」——Namespaces、Applications（聚合
  Deployment/DaemonSet/StatefulSet/裸 Pod）、Networking、Config、Volumes；聚合 API + 必要時
  直打原生 API。

## 4. Confirmed Decisions

1. 產品定調：**swallow 只管理我們自己佈署的東西**；非自部一概不管。唯一例外是 OS provisioning
   的 import existing Server（那是 provisioning 功能，不是 Platform 管理）。
2. 該原則**同時套用 Kubernetes 與 Slurm**：兩者都收掉「註冊既有叢集」的公開路徑。
3. 明確不做：import existing k8s cluster。
4. 交付策略：先寫整體產品架構（原則 + explorer + day-2 邊界），**第一波實作**是「只管自部」的
   收斂 + 叢集內資源瀏覽器（讀寫都要）；加減節點與 k0s upgrade 列為後續 day-2。
5. 既有 `origin=registered` 紀錄保留一版相容：可讀、可 Delete，不可 Uninstall、不可開 explorer；
   公開 API 不再產生新的 registered 紀錄。

## 5. Architecture and Design Principles

### 雙平面（borrow Rancher）

- **Lifecycle plane**：swallow 擁有的 Workflow（Temporal）。deploy / uninstall / repair 已有；
  未來 scale / upgrade 走這裡。長時間、durable、可取消。
- **Explorer plane**：對下游 Kubernetes API 的**即時讀寫**。同步呼叫、不建 Workflow、不落盤。
  用部署成功時存下的 Swallow-owned platform Integration（bearer token）連線。
- 兩個平面不得混成同一個 Operation。

### 資源樹（borrow Portainer CE）

- Platform 詳情底下做 type-specific 導覽（延續 ADR 021 共用 shell），不另開 `/planes`。
- Application 聚合：Deployment / DaemonSet / StatefulSet / 無 owner 的 Pod 合成一張表（從 Pod
  `ownerReferences` 回溯 ReplicaSet→Deployment）。Helm 先不當一等公民。
- Namespace 當隔離邊界：列表預設隱藏 system namespace（`kube-system`、`kube-public`、
  `kube-node-lease`），可切換顯示。
- 列表 / 詳情 / 動作走 swallow REST；建立與進階變更走 YAML `apply`（可選 server-side dry-run）。
  不做 Rancher Steve 式通用 `/k8s/clusters/{id}` proxy。

### 分層（Clean Architecture）

- `internal/platform/domain`：`KubernetesClusterClient` port + 意見化 view types（不 persist）。
- `internal/platform/application`：eligibility（deployed + kubernetes + integration）+ use case。
- `internal/platform/infra/platformapi`：把 `KubernetesReader` 擴成可寫 REST client（同一顆
  bearer token、同一套 TLS/`insecureSkipVerify`）。第一波不引入 `client-go`。
- membership sync 維持只讀 nodes；explorer 的 node 列表是另一條 on-demand 讀。

## 6. Functional Scope

### 收斂「只管自部」

- 移除 `POST /api/v1/platforms/`（註冊既有叢集）。Platform 只由 `POST /platforms/deploy` 產生。
- `POST /api/v1/integrations` 拒絕 `kind=platform`（含 `cluster` deprecated alias）。內部 deploy
  完成 hook 直接呼叫 `IntegrationRepository.Create`，不受影響。
- `PATCH /api/v1/platforms/{id}` 不再接受 `integrationId`（避免註冊後門）；其餘欄位仍可改。
- Dashboard 拿掉 kubernetes/slurm Integration 建立項；explorer 只在 `origin=deployed` 且
  `integrationId` 非空時啟用，否則降級回 Overview。

### Explorer MVP（讀寫）

新 Active 契約 `platforms-kubernetes.md`。端點（皆 admin JWT；非 kubernetes → 404；origin 非
deployed 或無 credential → 409/validation）：

- `GET /kubernetes` — 叢集摘要（version、node 數/Ready、namespace 數）
- Namespaces：`GET/POST /kubernetes/namespaces`、`DELETE /namespaces/{name}`
- Applications：`GET /kubernetes/applications?namespace=`（聚合）、
  `GET/DELETE /applications/{ns}/{kind}/{name}`、`POST .../restart`、`POST .../scale`
- Pods：`GET /kubernetes/pods?namespace=`、`GET .../pods/{ns}/{name}/logs?container=&tailLines=`
  （非 follow）、`DELETE`
- 附屬資源列表：`GET` Services / Ingresses / ConfigMaps / Secrets / PVCs（可選 `namespace`）
- `POST /kubernetes/apply` — YAML manifest；`dryRun=true` 只驗證
- Nodes：`GET /kubernetes/nodes`（含對到的 `serverId`）、`POST .../nodes/{name}/cordon|uncordon`

## 7. Constraints and Rules

- 遵守 ADR 001：workloads / node state / membership 是 live read，不進 Mongo；写入打 Kubernetes API。
- 遵守 Clean Architecture：k8s 型別不得洩進 `internal/platform/domain`；domain 定義 port 與意見化
  view types，infra 提供 REST 實作。
- 延續 ADR 021：explorer 是 on-demand read/write，不寫 membership axis、不動 sync 計數、不在
  reconcile interval 上跑。
- 憑證：部署產生的 token 目前掛 `cluster-admin`（`k0s_cluster_credential` role）。explorer 寫入
  沿用它；least-privilege 拆分不在第一波（ADR 註明「從 membership-read 升級為 cluster management」）。
- Secret list 不回傳明文 value；detail 才按需（第一波先不做 secret detail 明文）。

## 8. Data Model and Format Notes

- 新增 glossary term **Kubernetes Application**：一個「view aggregation」概念（Deployment /
  DaemonSet / StatefulSet / 無 owner 的 Pod），不是儲存實體、不是 CRD。
- Pending `Plane` 標為不做；不要用 pending `Workload` 當 API 名。
- `origin=registered` 與 `lifecycleState=registered` 仍存在於 read model（相容），但不再由公開
  API 產生新的 registered 紀錄。

## 9. CLI / API / Config Notes

## 10. Implementation Plan

1. 文件：手稿 + ADR 032 + glossary + Active 契約（互指、`/planes` superseded）。
2. 收斂：關掉 Platform 註冊與公開 `platform` Integration 建立；凍結 `integrationId` PATCH；
   Dashboard 拿掉 kubernetes/slurm 建立項；更新測試與 e2e fixture。
3. 後端 client：`KubernetesClusterClient` port + infra REST（含 Application 聚合）+ factory。
4. 後端 explorer：use case（eligibility + node 對齊）+ handlers + routes + 測試。
5. Dashboard：domain 型別、port + adapter、Kubernetes 專屬導覽（Applications / Namespaces /
   Cluster）+ scale/restart/delete/logs/apply/cordon；無憑證降級 Overview；e2e mock + spec。
6. 驗證：api-server 單元/契約測試與 dashboard e2e；保留 deploy/uninstall/membership 迴歸；
   coding-style 文件關卡。

## 11. Non-goals

- Import existing k8s / Slurm cluster；kubeconfig import / Portainer Agent / Edge。
- Rancher Project 多租戶、Norman `/v3`、Fleet GitOps。
- Per-user ServiceAccount 與 namespace ACL。
- kubectl shell、下載 kubeconfig（第一波）。
- 把 k8s 資源抄進 Mongo。
