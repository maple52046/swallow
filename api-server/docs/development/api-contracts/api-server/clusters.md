# Clusters

## Status

Active

## Owner Component

`api-server`

## Consumer Components

- `dashboard`

## Purpose

Register the Kubernetes and Slurm clusters swallow knows about, read their membership,
and deploy a new k0s cluster onto already-provisioned servers. swallow owns a cluster's
registration, its policy, and — for clusters it deploys — the intent to build it. It does
not own membership, which is read from the cluster's own API.

## Cluster Resource

```json
{
  "id": "cluster-id",
  "siteId": "site-id",
  "name": "lab-k0s",
  "type": "kubernetes",
  "integrationId": null,
  "gpuStackOwner": "provisioning",
  "exporterOwner": "ansible",
  "sync": {
    "lastStartedAt": null,
    "lastSucceededAt": null,
    "lastError": null,
    "memberCount": 0,
    "matchedCount": 0
  },
  "createdAt": "2026-08-26T00:00:00Z",
  "updatedAt": "2026-08-26T00:00:00Z"
}
```

`type` is `kubernetes` or `slurm`. `gpuStackOwner` is `provisioning` or `gpu-operator`
and has no default. `exporterOwner` is `ansible` (default) or `k8s`, and decides which
subsystem installs this cluster's Prometheus exporters; a member host's effective owner is
`unmanaged` when the machine is locked. `integrationId` is `null` until the cluster is
reachable, which is the normal state between deciding to build a cluster and having built
it. `sync.matchedCount` is how many members swallow matched to a server; a gap from
`memberCount` means the cluster contains machines swallow does not manage.

## Register An Existing Cluster

`POST /api/v1/clusters/` registers a cluster that already exists.

```json
{
  "siteId": "site-id",
  "name": "lab-k0s",
  "type": "kubernetes",
  "integrationId": "cluster-integration-id",
  "gpuStackOwner": "provisioning",
  "exporterOwner": "ansible"
}
```

`siteId`, `name`, `type`, and `gpuStackOwner` are required. `integrationId` and
`exporterOwner` are optional; `exporterOwner` defaults to `ansible`. Without
`integrationId` the cluster is registered but its membership cannot be read yet. Success
is `201 Created` returning the cluster resource.

## Deploy A New Cluster

`POST /api/v1/clusters/deploy` creates a cluster and starts a `deploy-kubernetes`
operation that builds it with k0s. It is distinct from registration because it both
creates the cluster and returns an operation to watch.

```json
{
  "siteId": "site-id",
  "name": "lab-k0s",
  "gpuStackOwner": "provisioning",
  "k0sVersion": "v1.36.3+k0s.2",
  "podCidr": "10.244.0.0/16",
  "serviceCidr": "10.96.0.0/12",
  "apiVip": "192.168.100.200",
  "apiVipPrefix": 24,
  "roleAssignments": [
    { "serverId": "server-a", "role": "control-plane" },
    { "serverId": "server-b", "role": "control-plane" },
    { "serverId": "server-c", "role": "control-plane" },
    { "serverId": "server-d", "role": "worker" }
  ]
}
```

`type` is always `kubernetes` for this endpoint and may be omitted. `k0sVersion`,
`podCidr`, `serviceCidr`, `apiVip`, and `apiVipPrefix` are optional; omitted values use
the installation defaults (`podCidr` `10.244.0.0/16`, `serviceCidr` `10.96.0.0/12`). The
VRRP password for the virtual IP is generated by swallow and never accepted from the
caller.

`roleAssignments` is required. Every referenced server must exist, be `deployed`, and
belong to `siteId`. `role` is `control-plane` or `worker`. The number of control-plane
assignments must be an odd number of at least three, so that etcd has a quorum. Neither
`podCidr` nor `serviceCidr` may contain any target server's address, because the nodes
reach each other over their own subnet.

Success is `202 Accepted` after the cluster and the pending operation are persisted, not
after the deployment completes:

```json
{
  "clusterId": "cluster-id",
  "operationId": "operation-id"
}
```

The deployment's progress is observed through the [operations](operations.md) endpoints.
On success swallow attaches a cluster-kind integration to the cluster and begins reading
its membership; the cluster resource's `integrationId` becomes non-null.

## List, Get, Update, Delete

`GET /api/v1/clusters/` returns a plain array of cluster resources, optionally filtered by
`siteId`. `GET /api/v1/clusters/{clusterId}` returns one. Both are small and bounded and
are not paginated.

`PATCH /api/v1/clusters/{clusterId}` updates `name`, `integrationId`, `gpuStackOwner`, or
`exporterOwner`; each field is optional and only provided fields change.

`DELETE /api/v1/clusters/{clusterId}` removes the registration and clears the membership
axis it produced, so no server is left claiming to belong to a cluster that no longer
exists. Deletion does not tear down the running cluster on the hosts.

## Sync Membership

`POST /api/v1/clusters/{clusterId}/sync` reads the cluster's membership now instead of
waiting for the background interval, and returns a report:

```json
{
  "clusterId": "cluster-id",
  "clusterName": "lab-k0s",
  "members": 7,
  "matched": 7,
  "cleared": 0,
  "unmatched": [],
  "error": null
}
```

`POST /api/v1/clusters/sync` syncs every registered cluster and returns an array of these
reports; one failing cluster does not stop the rest.

For a Kubernetes cluster, membership is read from `/api/v1/nodes`. When the cluster
integration enables control-plane lease discovery, dedicated controllers — which k0s does
not register as nodes — are additionally read from `k0s-ctrl-*` leases in
`kube-node-lease` and reported with role `control-plane`. `unmatched` names members
swallow could not match to a server, which is the part that needs a human.

## Errors

Unknown cluster, site, or integration returns `not_found`. A duplicate name at a site
returns `conflict`. Invalid type, invalid `gpuStackOwner`, invalid `exporterOwner`, an even or fewer-than-three
control-plane count, a target that is not `deployed`, targets spanning sites, or a
pod/service range covering a node address returns `validation_error`. A cluster with no
integration whose membership is requested returns `validation_error`; a missing cluster
credential returns `provider_unavailable`. Cluster API failures map per the cluster
reader: an auth or transport failure returns `provider_unavailable`, a rejected request
returns `validation_error`.

## Compatibility Notes

- `POST /api/v1/clusters/deploy` is additive; registration via `POST /api/v1/clusters/`
  is unchanged.
- `roleAssignments` uses the domain member-role vocabulary (`control-plane`, `worker`).
  The k0s term `controller` is an implementation detail of the playbook and never appears
  on the wire.
- Control-plane lease discovery is a per-integration setting rather than default
  behaviour, because the `k0s-ctrl-` lease naming is specific to k0s.
